## 1. 产品概述

### 1.1 背景

QuickDL 起源于一个很具体的个人需求：最近在学习 Qt 6，希望用一个真正有挑战、能长期使用的项目来掌握桌面应用开发；同时，作者为现有付费下载器充值了近一百元会员后，感受到这类工具有真实的商业价值，也想亲手做一个更适合“大文件单任务极速下载”的版本。界面目标不是通用工具风，而是使用热门动漫 IP 主题，让下载器本身成为有辨识度的二次元桌面应用。

第一阶段以自用和 Qt 学习为主，不把商业化和功能数量作为 MVP 目标。重点是验证一件事：自己写的下载核心，能不能在单任务大文件场景下做到足够快、足够稳、足够好看。

这个项目不是再做一个功能堆满的下载管理器，也不是把任务队列当成主产品。真正想解决的是：

- 下载几百 MiB 到数 GiB 的单个文件时，能否把服务器允许的并发和本机带宽吃满。
- 网速已经很快时，界面是否还能准确显示真实速度、真实进度和真实剩余时间。
- 断网、暂停、重启以后，能否继续下载而不是从头再来。
- 一个由自己掌控的桌面工具，是否可以同时做得够快、够稳、够好看。

### 1.2 产品定位

**工业级单任务下载引擎 + 极简操作 + 热门动漫 IP 主题界面。**

所谓“工业级”在本项目中指：

- 传输核心以吞吐、正确性、恢复能力和可观测性为第一优先级。
- 任务状态、文件落盘、断点续传和错误处理不能依赖“看起来能跑”的临时实现。
- 有可重复的性能基准、异常测试和崩溃恢复测试，而不是只靠主观感觉宣称“很快”。
- 为速度服务的并发调度、磁盘写入和网络重试必须有明确上限和降级策略。

产品不追求首版功能数量，也不以安装包体积作为核心卖点。界面保持轻量、聚焦，但底层按长期可维护的桌面软件标准建设。

### 1.3 产品目标

1. **单任务极速**：在服务器支持 Range 时，使用动态分块和最高 32 个并发传输通道，让一个任务尽量吃满可用带宽。
2. **大文件舒适**：优先优化 100 MiB～10 GiB 文件的下载体验，支持 64 位大小、预分配和断点恢复。
3. **进度真实**：所有百分比、速度、剩余时间都来自实际收到并写入磁盘的数据，不做虚假推进，不把未知大小伪装成确定进度。
4. **工业化可靠**：暂停、重启、断网、服务器限流、文件变化和磁盘错误都必须可解释、可恢复。
5. **视觉有辨识度**：采用热门动漫 IP 主题，让代表性角色、色彩和世界观与速度仪表、连接通道和任务状态融合，而不是普通表格加一个进度条。公开版本必须使用获得授权的 IP 素材。
6. **一套代码多平台**：使用 Qt 6 和跨平台 C++ 核心，交付 Windows、macOS、Linux 桌面版本。

### 1.4 MVP 成功标准

- 能稳定下载普通 HTTP/HTTPS 直链文件。
- 在受控测试环境中，单任务的多连接吞吐应明显高于单连接，并达到 aria2c 同级配置吞吐的 85% 以上；正式版目标为 95% 以上。
- 下载过程中强制结束进程，重新打开程序后可以继续下载，最终文件内容正确。
- 单任务 16 个并发通道下载 2 GiB 文件时，主界面保持可操作，进度与磁盘实际写入量一致。
- 未知总大小时不显示伪造百分比或伪造 ETA。
- 默认主题使用选定热门动漫 IP 的授权素材和视觉语言，并且在动画开启时不影响下载核心性能；授权未落地时开发版使用中性占位主题，不把未授权素材打入公开包。
- Windows、macOS、Linux 均能生成可启动的发布包。
- 所有 P0 需求通过验收，且没有会导致文件损坏或任务无法恢复的阻断级缺陷。

## 2. 用户与使用场景

### 2.1 目标用户

- 作者本人：正在学习 Qt 6，希望完成一个真正可用的桌面应用，而不是练习项目。
- 经常下载数百 MiB 到数 GiB 单个文件的用户：游戏资源包、安装包、数据集、镜像、音视频素材等。
- 对“下载速度是否真的跑满”和“界面是否有愉悦感”同样敏感的用户。
- 只需要 HTTP/HTTPS 直链，不需要登录态、网站解析或复杂自动化的用户。

### 2.2 核心场景

1. 用户复制一个 1.2 GiB 资源包直链，打开 QuickDL 后粘贴链接，确认保存位置后立即进入极速下载。
2. 用户想确认程序是否真的快：主界面实时展示从 1 MiB/s 爬升到数十 MiB/s 的速度曲线、当前工作通道数和实际写入进度。
3. 用户暂停任务，处理其他事情后继续，下载从已有偏移恢复，不重新下载已完成的数百 MiB。
4. 网络短时中断后自动重试；如果服务器限流，连接数自动回落，速度和状态同步向用户说明。
5. 用户添加多个链接时，默认只跑一个任务，把全部连接让给当前文件；其他任务排队，不抢占主任务带宽。
6. 用户关闭程序或系统重启，重新打开后看到未完成任务处于暂停状态，可安全继续。
7. 用户下载完成后，在二次元风格的任务卡片中查看最终大小、速度记录，并打开文件所在目录。
8. 用户遇到链接失效、签名过期、服务器拒绝、磁盘空间不足时，能看到明确原因和下一步操作。

### 2.3 前提与假设

- 下载地址是用户有权访问的 HTTP/HTTPS 直链，首版不处理网站登录、验证码和 Cookie。
- 文件由用户选定保存目录，程序不自动执行、解压或打开下载完成的文件。
- 服务器可能支持或忽略 Range；不支持 Range 时允许降级为单连接。
- “快到极致”受本机网络、磁盘、服务器限速、服务器并发策略和 TLS 开销共同限制，程序只能逼近这些条件的上限，不能突破物理带宽。
- 默认单活动任务是产品策略；用户确实需要同时下载多个小文件时，仍可通过设置允许 2～3 个活动任务，但会明确提示会分摊带宽和连接数。
- MVP 面向单用户、本机使用，不提供账号体系和多设备同步。

## 3. 产品范围

### 3.1 MVP 范围

#### P0：必须完成

- 添加 HTTP/HTTPS 直链任务。
- 文件保存目录选择。
- 单任务动态分块、多连接并行下载与单连接降级。
- 默认 16 个并发传输通道，最高可配置 32 个；带自适应爬升和安全回落。
- 针对 100 MiB～10 GiB 大文件的吞吐优化、磁盘预分配和 64 位进度。
- 暂停、继续、取消、重试。
- 轻量任务队列，默认只运行一个活动任务，多个链接不抢占主任务连接。
- 真实进度、实时速度、速度曲线、剩余时间和状态展示。
- 断点续传与程序重启恢复。
- 下载历史与基础设置。
- 文件重名处理、临时文件清理和最终文件原子落盘。
- 基础错误提示和操作建议。
- 热门动漫 IP 主题化能力，包括主题包、速度仪表、连接通道可视化、角色状态动效和授权素材替换。
- “减少动态效果”和“性能优先”外观模式，避免装饰层影响下载核心性能。
- Windows、macOS、Linux 构建与基本打包。

#### P1：后续增强

- 粘贴或拖入多个 URL 后批量创建任务。
- 全局下载限速和单任务限速。
- 自动从剪贴板识别链接。
- 搜索任务、按状态排序、下载完成通知、托盘常驻。
- 更多取得授权的热门 IP 主题包、角色皮肤和自定义强调色。
- 校验和验证、下载完成后自动校验。
- 英文界面与更多语言。
- Windows ARM64、Linux ARM64 版本。
- 手动代理配置、代理认证和更细的 HTTP 调优选项。
- 增量下载、镜像源择优和多 URL 回退。

#### P2：明确不进入 MVP

- 视频网站解析、网页媒体嗅探、登录态和 Cookie 管理。
- BT、磁力链接、ED2K 等 P2P 协议。
- 浏览器扩展、系统级 URL 接管。
- 计划下载、自动更新、账号体系和云端同步。
- 插件系统、脚本系统和第三方下载源适配。
- 移动端应用。

### 3.2 产品边界

**核心重，功能轻，视觉强。**

- **核心重**：传输引擎按工业级标准设计，支持动态分块、连接池、自适应并发、断点恢复和性能基准。
- **功能轻**：首版不铺开大量管理功能，用户打开后最醒目的永远是当前单任务和速度。
- **视觉强**：界面要有明确的二次元审美和速度感，但不能用虚假动画冒充真实进度。

产品默认把单任务放在绝对中心：

1. 新任务开始时优先获得全部连接预算。
2. 默认只运行一个活动任务，其他任务进入简单队列。
3. 用户明确打开多任务并发后，程序才拆分带宽和连接数，并显示资源分配提示。
4. 单个任务的峰值速度、稳定性和恢复正确性，优先于同时下载更多文件。

QuickDL 不承诺对所有服务器都能达到某个绝对速度。服务器可能按 IP、账号或单连接限速，也可能拒绝高并发请求。程序应优先保证正确性，再优化速度；当高并发导致 429、403 或明显降速时，必须自动降级而不是强行硬冲。

## 4. 功能需求

### 4.1 新建下载任务

| ID | 优先级 | 需求 |
| --- | --- | --- |
| FR-01 | P0 | 主界面提供“新建下载”入口，并支持 `Ctrl/Cmd + N` 快捷键。 |
| FR-02 | P0 | 新建任务窗口包含 URL、文件名、保存目录和“极速下载”按钮。文件名默认由服务器或 URL 推导，用户在开始前可以修改。 |
| FR-03 | P0 | 支持把 URL 文本拖入主窗口，或通过 `Ctrl/Cmd + V` 粘贴 URL。一次粘贴多个链接时，MVP 可以使用第一个有效链接并提示批量功能尚未开放。 |
| FR-04 | P0 | 仅接受 `http` 和 `https` 协议；空主机、`file://`、`ftp://` 等地址必须在开始前被拒绝。 |
| FR-05 | P0 | 默认保存目录为系统“下载”目录；用户可以修改，并应记住最近一次选择。 |
| FR-06 | P0 | 用户修改过的文件名优先于服务器返回的文件名。未修改时依次使用 `Content-Disposition`、最终重定向 URL 的路径、`download` 作为候选名称。 |
| FR-07 | P0 | 文件名必须清理路径分隔符、控制字符和平台非法字符，禁止通过文件名进行路径穿越。Windows 保留名、结尾空格和结尾句点需要特殊处理。 |
| FR-08 | P0 | 下载开始前检查保存目录是否存在、是否可写。若服务器给出总大小，则检查可用空间，至少保留 `文件大小 + 100 MiB` 的余量。 |
| FR-09 | P0 | 如果目标文件名已存在，自动生成 `文件名 (1).扩展名` 形式的新名称；完成落盘前如果再次发生冲突，重新分配名称。 |

### 4.2 服务器探测与动态分块

| ID | 优先级 | 需求 |
| --- | --- | --- |
| FR-10 | P0 | 任务开始后先执行元数据探测：发送 `GET` 请求并携带 `Range: bytes=0-0` 和 `Accept-Encoding: identity`。不要只依赖 HEAD。 |
| FR-11 | P0 | 探测响应头满足需要后立即中止正文传输，避免服务器忽略 Range 时先把整个文件下载一遍。 |
| FR-12 | P0 | 解析 `Content-Length`、`Content-Range`、`Accept-Ranges`、`ETag`、`Last-Modified`、`Content-Disposition` 和最终重定向地址。 |
| FR-13 | P0 | 最多跟随 10 次重定向。记录最终 URL。遇到重定向循环、TLS 错误或无法解析的响应时，任务进入失败状态并给出明确原因。 |
| FR-14 | P0 | 文件总大小使用 64 位整数保存，支持大于 4 GiB 的文件和 10 GiB 级的长期下载任务。 |
| FR-15 | P0 | 当总大小已知、服务器支持 Range 且文件不小于 16 MiB 时启用多连接下载。默认配置 16 个并发通道，用户可以在 4～32 之间配置；无法多连接时自动降级为 1 个通道。 |
| FR-16 | P0 | 使用动态分块，而不是把文件平均切成固定数量的长分段。建议块大小按 `clamp(total_bytes / (connections × 4), 4 MiB, 32 MiB)` 估算，并按 MiB 对齐。 |
| FR-17 | P0 | 分块必须覆盖完整文件区间且互不重叠。每个块记录 `[start_byte, end_byte]`，任务完成时所有块必须连续覆盖 `0` 到 `total_bytes - 1`。 |
| FR-18 | P0 | 传输通道采用工作窃取式调度：通道完成一个块后立即领取下一个未完成块，不能出现少数固定长分段拖慢结尾。 |
| FR-19 | P0 | 连接数爬升采用渐进策略：先启动 4 个通道，在约 1.5 秒观察窗内没有 429/5xx 且吞吐仍在提升时，逐步提升到用户配置值，避免开局瞬间冲击服务器。 |
| FR-20 | P0 | 如果吞吐在增加连接后不再提升，或服务器出现 429、503、连续超时，应降低并发并退避。用户选择的 32 连接是上限，不是必须打满的目标。 |
| FR-21 | P0 | 当服务器忽略 Range、返回 200 而不是 206、总大小未知或 Range 响应不合法时，自动降级为单连接顺序下载，并在任务详情中标记“不支持多连接/断点续传能力受限”。 |
| FR-22 | P0 | 同一主机默认最多 16 个并发传输请求，硬上限 32 个；请求上限必须计入所有活动任务，不能只按单任务计算。 |

### 4.3 单任务极速与数据传输

| ID | 优先级 | 需求 |
| --- | --- | --- |
| FR-23 | P0 | 默认只运行 1 个下载任务。多个任务进入简单 FIFO 队列，当前任务使用完整连接预算，队列不得抢占当前任务连接。 |
| FR-24 | P0 | 用户在设置中允许 2～3 个活动任务时，必须按任务数和主机请求上限分配连接预算，并显示“多任务会分摊带宽”的提示。 |
| FR-25 | P0 | 每个任务使用目标目录中的临时文件 `<文件名>.<task-id>.part`，任务之间不共享临时文件。已知总大小时预分配空间，并通过随机定位写入各分块数据。 |
| FR-26 | P0 | 所有下载内容必须流式写入磁盘，不得把完整文件或完整分块加载到内存。每个通道的缓冲区必须有总量上限，建议全局缓存预算不超过 64 MiB。 |
| FR-27 | P0 | 网络写入与磁盘写入必须有背压控制：磁盘持续写不动时暂停接收更多数据，不能通过无限增加内存缓冲来“制造快”的假象。 |
| FR-28 | P0 | 使用 libcurl multi 管理并发传输和连接复用。网络、文件写入、数据库写入都必须在工作线程执行，GUI 线程不得被同步 I/O 阻塞。 |
| FR-29 | P0 | 进度只根据已成功写入磁盘的字节数计算。重试、校验失败或数据丢弃时可以短暂保持但不允许把未确认数据计入完成度。 |
| FR-30 | P0 | 总进度在未重新开始任务前不得无故倒退。重新下载或源文件变化必须由用户明确确认，确认后进度归零并标明原因。 |
| FR-31 | P0 | 实时速度基于最近约 2 秒内确认写入的字节数计算，同时提供最近 60 秒速度曲线。速度数字使用稳定排版，不能因字体宽度变化造成跳动。 |
| FR-32 | P0 | 至少积累 2 秒有效速度样本后才显示 ETA；样本不足时显示“计算中”，速度波动过大时显示区间或“波动中”，不得用下载开始时的瞬时值硬推剩余时间。 |
| FR-33 | P0 | 网络错误、超时、连接重置、HTTP 408/429/5xx 可自动重试。每个块最多自动重试 3 次，采用约 1、2、4 秒的指数退避，并从已保存偏移继续。 |
| FR-34 | P0 | 401、403、404、410 等不可恢复的客户端错误不应自动盲目重试，直接标记失败并展示 HTTP 状态码。429 响应带有 `Retry-After` 且等待时间不超过 60 秒时可以按提示等待。 |
| FR-35 | P0 | 每次重试或并发调整都要记录原因和当前连接数，便于用户查看“为什么速度降了”。调试面板可显示活跃连接、已完成块、重试次数和磁盘吞吐。 |
| FR-36 | P0 | 任务完成后必须校验总写入字节数和服务器给出的总大小一致；所有分块必须连续、无重叠、无缺口。校验通过后才能把临时文件重命名为最终文件。 |
| FR-37 | P0 | 临时文件和最终文件必须位于同一文件系统、同一目标的父目录中，以保证重命名是原子操作。完成前不得让临时文件出现在用户可见的最终文件名上。 |
| FR-38 | P0 | 单任务默认 16 连接的目标不是某个固定 MB/s，而是逼近“服务器允许的并发 × 本机可用带宽”的上限。任何公网速度表现都必须标注测试环境。 |

### 4.4 暂停、恢复与文件一致性

| ID | 优先级 | 需求 |
| --- | --- | --- |
| FR-39 | P0 | 持久化保存任务的最终 URL、临时文件路径、总大小、每个分块的区间和已完成偏移、连接配置、ETag 和 Last-Modified。 |
| FR-40 | P0 | 暂停时停止发起新请求，终止当前请求，刷新并保存每个块的实际写入偏移，保留临时文件。 |
| FR-41 | P0 | 继续时优先恢复未完成块；对于部分完成的块，从该块已完成偏移发出新的 Range 请求，不得覆盖已完成数据。 |
| FR-42 | P0 | 程序重启后，未完成任务默认恢复为“已暂停”，由用户确认后继续，避免启动时产生意外流量。 |
| FR-43 | P0 | 从暂停状态恢复或重启后恢复时，重新探测服务器元数据。若 ETag 或 Last-Modified 与首次下载不一致，禁止继续拼接，提示“源文件已变化”，由用户选择重新下载。 |
| FR-44 | P0 | 如果服务器没有 ETag 和 Last-Modified，则至少比较总大小。大小一致时允许继续，但在任务详情中提示“服务器未提供文件校验信息”。 |
| FR-45 | P0 | 如果探测结果显示总大小或 Range 能力与之前不一致，按不安全恢复处理，允许用户从零重新下载。 |
| FR-46 | P0 | 下载过程中每 1 秒或每完成 8 MiB 数据至少持久化一次分块进度；暂停、失败、退出时必须强制刷新。允许崩溃丢失最后一次未持久化的少量数据，但不得导致最终文件被误判为完整。 |
| FR-47 | P0 | 若恢复时发现临时文件缺失、无法在目标目录创建，或无法定位写入已记录的偏移，任务进入失败状态，禁止继续写入，避免产生空洞文件。 |
| FR-48 | P0 | 完成前刷新文件缓冲区并关闭文件句柄；最终校验失败时保留临时文件并进入失败状态，不得重命名为完成文件。 |

### 4.5 任务列表与历史

| ID | 优先级 | 需求 |
| --- | --- | --- |
| FR-49 | P0 | 主界面以当前活动任务为视觉中心，展示文件名、真实进度、实时速度、ETA、速度曲线、活跃连接数和可用操作。 |
| FR-50 | P0 | 历史区域使用紧凑列表展示其他任务，支持按“全部、下载中、已完成、失败/已暂停”筛选；历史不得挤压当前任务主视觉。 |
| FR-51 | P0 | 任务右键菜单或行内操作至少包含：暂停/继续、重试、取消、打开所在目录、从列表移除、删除本地文件（仅对可删除项显示）。 |
| FR-52 | P0 | 已完成任务显示最终文件名和文件大小；用户可以打开所在目录。打开目录失败时显示可操作的错误提示。 |
| FR-53 | P0 | 下载失败任务保留在历史中，显示错误摘要。用户可查看详情，包括 URL、HTTP 状态、错误码、连接数和可恢复操作。 |
| FR-54 | P0 | 关闭主窗口且仍有活动任务时，任务应暂停并保存状态，然后退出程序；关闭前如果存在活动任务，明确提示“下载将暂停”。 |
| FR-55 | P0 | 历史记录和设置重启后仍然保留。提供“清空已完成历史”操作，不影响本地文件。 |
| FR-56 | P0 | 取消任务时停止网络请求、关闭文件句柄。若已有部分数据，删除任务前需要用户确认，并明确“删除未完成文件”。 |
| FR-57 | P0 | 删除已完成任务的历史记录默认不删除本地文件；只有用户明确选择“同时删除本地文件”时才执行文件删除，并需要二次确认。 |

## 5. 界面与交互

### 5.1 主窗口结构

```text
主窗口
├── 顶部区域：品牌标识 / 新建下载 URL 输入 / 设置
├── 主舞台：当前任务
│   ├── 文件名、状态、保存位置
│   ├── 环形速度仪表 + 线性真实进度
│   ├── 已下载 / 总大小 / 实时速度 / ETA
│   ├── 最近 60 秒速度曲线
│   ├── 活跃连接通道可视化
│   └── 暂停、继续、打开目录、详情
├── 侧边或底部折叠区：队列与历史任务
└── 底部状态：活动任务、连接数、重试数、调试入口
```

### 5.2 主界面要求

- 默认窗口尺寸建议为 1200 × 760，最小尺寸 980 × 640。
- 窗口支持缩放；任务列表滚动时不阻塞下载更新。
- 当前活动的单个任务拥有最大视觉权重。队列和历史默认折叠为侧栏或底部面板，避免变成“任务管理后台”。
- 没有任务时显示空状态：选定热门 IP 的角色或主视觉、产品名、一句话说明和“新建极速下载”按钮。授权未完成时使用中性占位图。
- 任务操作至少覆盖暂停/继续、取消、重试、打开目录和查看详情。
- 状态必须同时通过文字、图标和颜色表达，不能只靠颜色区分。
- 实时速度、进度、ETA 与连接状态必须来自真实采样；界面装饰层不得修改这些数据。
- 速度数字使用等宽数字或表格数字特性，单位在 B/s、KiB/s、MiB/s、GiB/s 之间平滑换算，但样式保持稳定。
- 主进度条只根据实际写入字节数推进。总大小未知时使用不确定状态，不显示百分比，也不让进度条反复模拟“即将完成”。
- ETA 在样本不足时显示“计算中”；波动过大时显示“波动中”，不允许伪造一个看起来精确但不可信的秒数。
- 活跃连接可视化只点亮真实工作的通道；空闲、退避和失败通道要用不同状态表达。
- 任务列表支持单选；多选和批量操作不属于 MVP。
- 任务操作按钮在任务状态下变化：
  - 下载中：暂停、取消。
  - 已暂停：继续、取消。
  - 已完成：打开目录、从列表移除。
  - 失败：重试、查看详情、移除。
- 提供键盘操作和焦点态。至少支持 `Ctrl/Cmd + N` 新建、`Ctrl/Cmd + V` 在新建窗口粘贴 URL、`Esc` 关闭弹窗。
- 关闭窗口时始终优先保存真实进度和临时文件，不得因为动画或界面状态异常而跳过落盘。

### 5.3 新建下载窗口

- 字段：URL、文件名、保存位置、高级选项。
- 高级选项默认折叠，包含并发通道数（4～32，默认 16）。
- 主按钮文案使用“极速下载”，并清楚展示当前连接配置；普通用户无需进入高级选项即可获得最佳默认速度。
- 开始前校验 URL 和文件名，错误显示在对应字段附近。
- 下载开始后，URL 和并发通道数不可修改。
- 点击“极速下载”后关闭弹窗，把任务加入列表；元数据探测和网络请求在后台执行。
- URL 格式、协议或文件名等本地校验错误留在弹窗中，不创建任务。通过本地校验后，网络或服务器错误应创建失败任务并展示可重试原因，避免用户输入丢失。
- 新建窗口应保留最近一次保存目录和连接配置，减少重复操作。

### 5.4 状态文案

| 内部状态 | 用户可见文案 |
| --- | --- |
| Queued | 排队中 |
| Probing | 正在获取文件信息 |
| Downloading | 下载中 |
| Paused | 已暂停 |
| Completing | 正在完成 |
| Completed | 已完成 |
| Failed | 下载失败 |
| Canceled | 已取消 |

### 5.5 视觉方向：热门动漫 IP × 轻科幻速度

视觉目标不再以原创角色为默认方案。界面需要围绕一个明确的热门动漫 IP 建立主题，核心方向是**IP 角色与世界观 + 机械速度感 + 二次元轻盈感**，不采用通用企业软件式的灰色表格界面。

具体 IP 尚未选定前，使用中性的“IP Theme Slot”占位主题进行布局和性能开发。正式主题名、角色、Logo、主视觉和配色需要根据获授权的 IP 决定。

建议色板：

| 角色 | 颜色 | 用途 |
| --- | --- | --- |
| 深空背景 | `#0B1022` | 默认主背景 |
| 霓虹青 | `#46E6FF` | 主速度、主要操作、焦点态 |
| 樱花粉 | `#FF7BB5` | 强调、装饰、角色氛围 |
| 薄荷绿 | `#63F5C8` | 完成、健康状态 |
| 琥珀黄 | `#FFC45C` | 暂停、等待、拥塞提示 |
| 警报红 | `#FF5D7A` | 失败、不可恢复错误 |
| 主文字 | `#EDF7FF` | 标题与关键数字 |
| 次文字 | `#8EA4C7` | 说明与次要信息 |

建议布局尺度：

- 使用 8 px 基础栅格；卡片圆角 16～24 px，控件圆角 10～14 px。
- 顶部导航高度约 64 px；当前任务主卡片占主要宽度，历史区域默认宽 300～360 px 或折叠为底部抽屉。
- 速度仪表直径建议 180～220 px；实时速度数字 40～56 px；线性进度条高度 10～14 px。
- 速度曲线高度约 120～160 px，坐标轴文字保持弱化，避免抢过当前速度。
- 窗口宽度低于 1000 px 时，队列与历史自动收进抽屉，不压缩当前任务的进度与操作区域。
- 主要按钮点击区域不小于 44 × 44 px；危险操作与普通操作在颜色和位置上明确区分。

视觉要求：

- 使用选定热门动漫 IP 的官方素材、获得书面许可的同人素材，或已明确取得衍生使用权的定制插画。未经授权的角色、Logo、声优语音和音乐不得进入公开发布包。
- 空状态、当前任务主卡片和侧栏可以使用 IP 角色插画；运行中可以让角色动效与真实速度状态关联，例如待机、加速、拥塞、完成。
- IP 素材不能遮挡进度、速度、操作按钮和错误信息。角色、贴纸和装饰层必须为信息层级让位。
- 速度表盘、连接通道和速度曲线是主要视觉元素，不能只作为装饰贴图。
- 卡片使用圆角、细描边、局部霓虹光晕和轻微玻璃质感。大面积模糊和实时重粒子效果只用在非关键区域。
- 进度条使用清晰的亮色前缘和真实百分比；装饰光效不能越过尚未完成的真实位置。
- 角色动画不能暗示虚假完成度。下载停滞时角色应表现为等待或拥塞，而不是继续播放“冲刺”动画。
- 主题可以更换颜色、角色图和装饰，但速度、警告、完成和错误等状态色必须保持可辨识，不能完全被 IP 配色覆盖。
- 字体必须合法可分发，优先选择可商用的开源中文字体。数字使用 tabular figures 或等宽数字，避免速度跳动时版面抖动。
- 图标采用统一线宽和圆角风格，随应用打包 SVG，不依赖网络资源。
- 默认使用深色主题；浅色主题作为 P1。MVP 至少交付一套完整、精细的 IP 深色主题或其授权前占位版本。

### 5.6 动效与性能

- 默认动效模式为“平衡”：保留速度表盘、真实进度光效、连接通道状态和角色状态动画。
- “沉浸”模式可增加粒子、速度线和背景流光，但必须提供开关。
- “性能优先”模式关闭粒子、模糊、Shader 特效和角色连续动画，只保留状态转换。
- 动效目标为流畅的 30～60 FPS，不得占用下载核心线程。GPU 或系统不支持复杂效果时自动降级。
- 尊重系统“减少动态效果”设置；用户明确设置优先。
- 下载开始后如果界面动画导致明显 CPU/GPU 占用或帧率下降，应自动降低效果等级并记录原因。
- 所有进度和速度动效的位移都应由真实数据驱动。速度从 0 到峰值时可以有平滑插值，但不得在数据不变时持续制造“速度感”。

### 5.7 适配与可访问性

- QML 界面使用 Qt Quick Controls 2 和可复用的任务卡片组件。
- 支持高 DPI 和不同缩放比例，图标不能因缩放出现模糊。
- 所有用户可见字符串使用 Qt 翻译机制，MVP 提供简体中文。
- 不依赖网络加载界面资源，图标和字体随应用打包。
- 所有交互控件具备键盘焦点、可读标签和清晰对比度；动画关闭后核心功能仍完整可用。
- 错误信息不能只通过红色光效表达，必须提供文字说明和可执行操作。

### 5.8 热门 IP 主题包与授权策略

#### 5.8.1 主题包结构

主题包必须与程序代码解耦，避免每次更换 IP 都重写界面：

```text
themes/<theme-id>/
├── theme.json          # 主题名、IP 名称、颜色、动效等级、资源清单
├── images/             # 角色、Logo、背景、空状态和状态插图
├── icons/              # 授权范围内的自定义图标
├── fonts/              # 仅在许可证允许时随包提供
└── LICENSE-NOTICE.md   # 授权范围、版权方和素材来源
```

`theme.json` 至少包含：

- 主题 ID、显示名称、目标 IP 名称和版本。
- 色板、字体引用、动效配置、默认窗口背景和角色资源。
- 素材来源、版权方、授权文件编号或内部授权记录。
- 允许的分发范围、地区、期限和是否需要署名。

#### 5.8.2 三种发布模式

| 模式 | 素材来源 | 是否可公开分发 | 要求 |
| --- | --- | --- | --- |
| 本地自用原型 | 用户自行放入本地主题包中的图片或音频 | 否 | 不提交到公开仓库，不随安装包分发，不上传服务器 |
| 免费公开版 | 权利方书面许可、官方素材授权或合法合作 | 是 | 免费不等于免除版权；授权范围必须覆盖免费公开渠道 |
| 商业发布版 | 签署正式 IP 授权或联名协议 | 是 | 明确地域、期限、渠道、角色、宣传素材、衍生创作和终止条款 |

开发阶段的默认策略：

1. 先完成“IP Theme Slot”占位主题，不阻塞引擎和交互开发。
2. 选定 IP 后单独接入主题包，不改写下载核心。
3. 未拿到授权前，不把角色图、Logo、官方截图、声优语音或 IP 音乐放入可分发安装包。
4. 公开构建应能在没有本地主题包时正常启动，并回退到中性占位主题。

#### 5.8.3 授权清单

正式接入热门 IP 前，至少确认以下素材的授权状态：

- 角色形象、服装、道具和标志性视觉元素。
- 作品 Logo、标题字体和官方主视觉。
- 官方插画、动画截图、周边图案和 UI 图标。
- 声优语音、角色音效、主题曲和背景音乐。
- 使用场景是否包括桌面软件、安装包、商店页面、宣传图和视频。
- 是否允许修改、裁切、二次创作和制作动态效果。
- 是否要求署名、版权声明、版本限制和下线机制。

委托绘制同人插图并不自动取得 IP 授权；画师的著作权和权利方的角色权需要分别确认。具体授权以与权利方签署的合同为准。

## 6. 任务状态机

| 当前状态 | 允许转换 | 触发条件 |
| --- | --- | --- |
| Queued | Probing、Canceled | 获得活动槽位或用户取消 |
| Probing | Downloading、Paused、Failed、Canceled | 元数据有效、用户暂停、探测失败或取消 |
| Downloading | Paused、Completing、Failed、Canceled | 用户操作、所有分块完成、不可恢复错误或取消 |
| Paused | Probing、Downloading、Canceled、Failed | 用户继续、恢复校验失败或临时文件损坏 |
| Completing | Completed、Failed | 文件校验与原子重命名成功或失败 |
| Completed | 已完成历史状态 | 终态，可打开目录或移除记录 |
| Failed | Probing、Canceled | 用户重试或取消 |
| Canceled | 记录移除 | 终态，清理临时文件 |

约束：

- 所有状态变更必须由下载管理层统一处理，QML 不得直接修改任务状态。
- 终态 `Completed` 不能被自动转换为下载中；用户必须创建新任务才能重新下载。
- 失败重试必须重新探测元数据，不能无条件复用之前的 Range 结果。
- 任何文件删除或未完成数据移除都必须经过用户确认。

## 7. 下载算法与文件落盘

### 7.1 元数据探测

1. 规范化用户 URL，只允许 HTTP/HTTPS。
2. 发送带 `Range: bytes=0-0` 的 GET 请求，设置合理的 User-Agent 和 `Accept-Encoding: identity`。
3. 跟随最多 10 次重定向，并记录最终 URL。
4. 解析响应头和状态码：
   - `206 Partial Content`：优先解析 `Content-Range` 中的总大小。
   - `200 OK`：可能是服务器忽略 Range，按单连接处理。
   - `4xx/5xx`：按错误类型处理，不做无意义重试。
5. 探测响应头足够后，立即中止探测请求的正文传输，避免服务器忽略 Range 时把整个文件下载两遍。
6. 如果响应无法获得总大小，但可以创建文件，则允许单连接流式下载。
7. 根据总大小、Range 支持情况和用户连接配置生成下载计划。

### 7.2 动态分块

1. 设用户配置的并发上限为 `C`，默认 16。
2. 设文件总大小为 `S`，建议块大小为：

   ```text
   chunkSize = clamp(roundUp(S / (C × 4), 1 MiB), 4 MiB, 32 MiB)
   ```

3. 将文件按 `chunkSize` 从 0 开始顺序切分为互不重叠的块，最后一块允许小于标准块大小。
4. 每个块保存 `start_byte`、`end_byte`、`bytes_done` 和状态。块内部分下载后，继续时只请求剩余区间。
5. 块大小可以根据实测请求开销和吞吐做一次调整，但任务运行中改变块大小必须保持区间不重叠、不丢字节。

### 7.3 工作窃取调度

- 维护一个未完成块队列和一组活跃传输槽位。
- 初始启动 4 个槽位，随后按 1.5 秒窗口观察吞吐；没有触发限流且吞吐仍有提升时，逐步提升到用户配置的连接数。
- 任一槽位完成当前块后，立即领取下一个未完成块，形成工作窃取式调度。
- 不允许把文件预先切成 `C` 个巨大的固定分段后等待最慢的一段收尾。
- 每个传输请求都必须校验 HTTP 206 和 `Content-Range`。服务器对范围请求返回 200、范围不匹配或范围越界时，该请求不能写入文件。
- 并发提升后如果吞吐没有继续提升，保持当前有效连接数；如果出现限流或错误，自动降低并发。
- 服务器返回 429 时优先遵守 `Retry-After`，并将有效连接数降低到至少一半；退避结束后缓慢恢复，不得立即重新打满。
- “用户配置 32 连接”表示并发上限，不代表每一秒都必须使用 32 个连接。

### 7.4 速度与进度采样

- 任务进度 = 所有块已确认写入磁盘的字节数之和，不使用网络层收包数或界面动画推算值。
- 每个写入回调成功返回后，才把对应字节计入进度。
- 实时速度使用最近约 2 秒的已确认字节增量计算；速度曲线保存最近 60 秒的采样点。
- 至少 2 秒有效样本后才计算 ETA。ETA 使用近期稳定吞吐，而不是单个瞬时速度。
- 总大小未知时，进度显示为不确定状态，并只展示已写入字节、实时速度和连接数。
- 重试不会把已确认写入的数据再次计入进度；重新下载必须清空进度并取得用户确认。
- 校验失败或分块重下时，进度可以暂停在当前真实值，不得为了“顺滑”持续向前爬。

### 7.5 流式写入与背压

- 临时文件位于最终保存目录中，名称为 `<最终文件名>.<task-id>.part`。
- 已知总大小时预分配文件空间；未知总大小时顺序追加。
- 每个块写入前定位到对应偏移。建议通过跨平台随机写文件接口实现，例如 POSIX `pwrite` 和 Windows 定位写，避免多个回调共享文件游标。
- 网络缓冲区、写队列和回调缓冲必须有固定上限；建议全局缓存预算不超过 64 MiB。
- 当磁盘写入队列持续积压时，暂停接收新的网络数据或减少活跃连接，形成背压。
- 不得通过无限缓存下载数据来维持界面上的高速度。磁盘无法跟上时，应展示真实瓶颈。
- 写入失败（空间不足、权限、I/O 错误）必须立即停止相关块，并把错误映射为用户可理解的状态。

### 7.6 完成与清理

1. 停止所有传输槽位，等待正在写入的回调安全结束。
2. 刷新并关闭文件句柄。
3. 校验块覆盖范围、已写总字节数和服务器给出的总大小。
4. 通过最终重命名把 `.part` 文件变为目标文件。
5. 在数据库中把任务标记为 Completed，并清理不再需要的块明细。
6. 失败或取消时保留可恢复的 `.part` 文件，直到用户确认删除；程序不得在后台静默删除用户可见目录中的数据。

## 8. 错误处理与用户提示

| 错误类别 | 显示文案示例 | 默认处理 |
| --- | --- | --- |
| 网络不可达/DNS 失败 | 无法连接到服务器 | 自动重试 3 次，失败后提供“重试” |
| 连接超时/响应超时 | 服务器响应超时 | 自动重试 3 次 |
| TLS 证书错误 | 无法验证服务器证书 | 不绕过证书校验，提示检查系统时间或网络 |
| HTTP 401/403 | 服务器拒绝访问该文件 | 不自动重试，显示 HTTP 状态 |
| HTTP 404/410 | 文件不存在或链接已失效 | 不自动重试 |
| HTTP 408/429/5xx | 服务器暂时不可用 | 指数退避重试；429 可参考 Retry-After |
| Range 不合法 | 服务器返回了不完整的数据范围 | 重新探测；必要时降级单连接 |
| 不支持 Range | 服务器不支持多连接下载 | 自动降级为单连接，允许继续但不能保证断点续传 |
| 磁盘空间不足 | 磁盘空间不足 | 暂停任务，保留临时文件，提示更换目录或清理空间 |
| 无写权限 | 无法写入保存目录 | 不自动换目录，提示用户重新选择 |
| 源文件已变化 | 服务器文件已更新，无法安全续传 | 保留临时文件，提供“重新下载” |
| 临时文件损坏 | 本地临时数据不完整 | 任务失败，提供“重新下载”和“删除未完成文件” |
| 未知错误 | 下载失败 | 显示错误码和日志入口，允许重试 |

要求：

- 错误提示必须说明发生了什么和用户可以做什么。
- 自动重试不能在界面上造成状态闪烁；可以显示“正在重试（1/3）”。
- 原始 URL 可能包含签名参数，日志和错误详情中应默认隐藏查询参数中的敏感值。
- 失败任务不能自动删除临时文件，避免用户无感知地丢失可恢复进度。

### 9.3 持久化规则

- SQLite 开启 WAL 模式，所有状态写入使用事务。
- 程序启动时执行数据库结构版本检查，必要时迁移。
- 未完成任务启动后恢复为 Paused；临时文件存在且元数据可用时允许继续。
- 已完成的记录不再保留分块明细，避免数据库无限增长。
- 日志采用滚动文件，默认保留最近 7 天；不记录完整敏感 URL、Cookie 或磁盘路径之外的用户隐私数据。

## 10. 技术架构

### 10.1 总体分层

```text
QML Views + Qt Quick Effects
   ↓ 属性、信号、模型
C++ UI Models / ViewModels
   ↓
DownloadService / DownloadTask 状态机
   ↓
ChunkPlanner / SpeedGovernor / ConnectionScheduler
   ↓
libcurl multi（独立工作线程）
   ↓
RandomAccessFileWriter + 有界缓冲 + 背压
   ↓
SQLite 持久化 + 日志
   ↓
Windows / macOS / Linux 平台集成
```

### 10.2 组件职责

| 组件 | 职责 |
| --- | --- |
| QML Views | 主窗口、当前任务主舞台、历史列表、新建窗口、设置页；只负责展示和用户交互 |
| DownloadListModel | 向 QML 暴露任务角色和状态变化 |
| ThemeManager | 加载本地主题包、校验资源清单、切换 IP 主题并回退到中性占位主题 |
| DownloadService | 单任务优先的队列、活动任务数、连接预算和全局状态 |
| DownloadTask | 单个任务的状态机、重试、恢复和完成校验 |
| ChunkPlanner | 根据总大小和并发上限生成动态分块 |
| ConnectionScheduler | 工作窃取、渐进爬升、限流降级和连接池管理 |
| CurlMultiWorker | 在专用工作线程运行 `curl_multi` 事件循环，处理 Range 请求、超时、代理由和连接复用 |
| RandomAccessFileWriter | 预分配、随机定位写入、背压、刷新、原子重命名和临时文件清理 |
| SpeedMeter | 基于真实写入字节计算 2 秒速度、60 秒曲线和 ETA 可用性 |
| TaskRepository | SQLite 的增删改查和启动恢复 |
| PlatformBridge | 系统下载目录、打开/显示文件、系统代理和平台差异处理 |
| Logger | 本地滚动日志、错误码和敏感信息脱敏 |

### 10.3 线程与响应性

- GUI 线程只处理 QML 渲染和轻量状态转换。
- libcurl multi、文件写入、数据库写入和校验计算放在工作线程或异步任务中。
- 使用 queued connection 把任务进度节流后发送给 UI。
- 任务取消必须线程安全；取消后不得再写文件或修改已关闭的任务数据库记录。
- 任何单个 GUI 线程阻塞操作不得超过 100 ms；文件系统操作失败要有超时或明确的异步结果。
- 下载线程与 UI 之间使用有界消息队列。UI 渲染变慢时，进度消息只能合并或丢弃中间帧，不能反过来阻塞下载。
- 动效和速度可视化只能读取已发布的采样快照，不能直接访问 libcurl 或文件句柄。

### 10.4 技术约束

- 使用 Qt 6.8 LTS 作为基线版本，C++20 和 CMake 构建。
- UI 使用 Qt Quick/QML，业务逻辑放在 C++。
- 首版使用 libcurl multi 完成传输。Qt 仍然是应用框架，libcurl 只是像 SQLite 一样承担专业传输职责的底层组件。
- 选择 libcurl 而非 Qt Network 的原因：需要更细粒度的多连接控制、连接复用、限流响应、超时处理和 `curl_multi_poll` 事件循环，以便支撑 16～32 路 Range 传输。
- libcurl 8.x 版本需要固定并在三平台回归测试；发布构建必须使用可重复的依赖获取方式，不允许悄悄跟随系统版本漂移。
- TLS 必须使用受信任的系统证书链或随包维护的 CA，不提供关闭证书校验的快捷开关。
- 传输层与 UI 层之间定义稳定的任务事件接口，方便后续测试、压测和替换底层实现。
- 不引入浏览器内核、Electron 或运行时 WebView。
- 不将下载逻辑、路径拼接或文件读写放进 QML。
- 热门 IP 视觉资源必须具有明确授权或仅用于不分发的本地原型；公开包不得包含未授权素材，也不依赖外部网络加载。

## 11. 非功能需求

### 11.1 兼容性

| 平台 | MVP 目标 |
| --- | --- |
| Windows | Windows 10 22H2 及 Windows 11，x64 |
| macOS | macOS 13+，Apple Silicon 与 Intel 双架构；可以采用 Universal 包或两个独立包 |
| Linux | Ubuntu 22.04+、Fedora 40+ 或等效发行版，x86_64；X11 和 Wayland 至少各做一次完整下载测试 |

共同要求：

- 支持中文文件名、空格、括号和 Unicode 路径。
- 支持高 DPI。
- 不同平台使用系统下载目录和应用数据目录。
- 网络不可用、代理不可用和证书错误必须可恢复或可解释。
- 三个平台必须使用同一套任务状态、分块算法和数据库迁移逻辑，不允许平台行为分叉到无法互测。
- Windows ARM64 和 Linux ARM64 作为 P1；架构支持不要阻碍后续交叉编译。

### 11.2 性能

- 在常见 SSD 和普通网络环境下，冷启动目标不超过 3 秒。
- 空闲状态 CPU 占用目标低于 2%。
- 单任务 16 个并发通道下载 2 GiB 文件时，应用内存目标低于 220 MiB，且不随文件大小线性增长。
- 文件传输使用流式写入，下载 10 GiB 文件时不得把完整文件或完整分块读入内存。
- 动画开启时，主界面渲染目标为 30～60 FPS；界面卡顿不能反向阻塞网络和磁盘写入。
- 单任务从 4 个通道爬升到 16 个通道的目标时间不超过 5 秒。
- 速度采样窗口约 2 秒，UI 每秒刷新不超过 10 次；速度曲线保留最近 60 秒。
- 在受控 1 Gbps 网络、SSD、支持 Range 且按单连接限速的测试服务器上，使用 2 GiB 固定文件连续测试 3 次：
  - 16 通道的单任务中位吞吐应至少达到单连接中位吞吐的 6 倍。
  - 同级连接配置下，中位吞吐应达到 aria2c 的 85% 以上；正式版目标为 95% 以上。
- 在服务器按 IP 总带宽限速、磁盘成为瓶颈或代理质量较差时，不承诺加速倍数。界面应如实展示实际速度。

### 11.3 性能验证方法

性能指标必须使用固定、可重复的测试环境，不能只用某一次公网下载截图证明。

| 项目 | 要求 |
| --- | --- |
| 测试文件 | 至少包含 100 MiB、2 GiB、5 GiB 三种固定文件 |
| 测试服务 | 本地 HTTP 服务，支持 Range、固定 Content-Length、可选单连接限速 |
| 对照组 | 1 连接、4 连接、16 连接、32 连接；aria2c 同级配置 |
| 样本 | 每组至少 3 次，报告中位数和波动范围 |
| 记录项 | 平均吞吐、峰值吞吐、完成时间、重试数、峰值内存、磁盘写入速度 |
| 正确性 | 每组完成后校验 SHA-256，并比对文件大小 |

如果客户端读取文件、界面动画、数据库写入或磁盘缓存污染了吞吐结果，必须定位瓶颈后重测，不能直接拿最高一次作为结论。

### 11.4 可靠性

- 未完成下载结束后不得被标记为完成。
- 最终文件只能通过校验后的原子重命名产生。
- 进程崩溃、系统注销或网络断开后，临时文件和已保存进度应可继续使用。
- 对分块重叠、缺失、越界、服务器返回错误范围等情况必须检测并失败，不得静默拼出损坏文件。
- 数据库写入失败不能导致 UI 假报完成。
- 并发爬升、限流降级和重试不能造成任务状态互相覆盖；所有事件必须进入单一状态机处理。
- 连续暂停/继续、快速退出、长时间暂停后恢复都必须保持文件一致。

### 11.5 安全与隐私

- 只允许 HTTP/HTTPS URL，拒绝本地文件和命令执行类协议。
- 始终保持 TLS 证书验证，不提供默认关闭证书验证的选项。
- 对文件名进行路径穿越和非法字符清理，最终路径必须位于用户选择的保存目录内。
- 下载完成后不自动执行、不自动解压、不自动打开未知文件。
- 不在日志中记录完整敏感 URL 查询参数、Cookie 或认证头。
- 不内置遥测；如需统计信息，必须另行设计并明确征得用户同意。
- 热门 IP 角色、插画、Logo、语音和图标必须具有合法授权；本地自用主题包不得随公开安装包分发。
- 动效和装饰性 Shader 不得加载远程脚本或网络字体。

### 11.6 发布与许可证

- Qt 开源版发布需要遵守 LGPL 条款，优先采用动态链接并随包提供许可证和第三方声明。
- libcurl、OpenSSL 或其他 TLS 依赖需要逐一整理许可证和版本信息，随安装包提供第三方声明。
- 如果业务需要静态链接、闭源分发或进入有额外限制的应用商店，应单独评估 Qt 商业许可。
- macOS 公开发布需要代码签名和 notarization；Windows 公开发布建议进行代码签名，避免 SmartScreen 首次运行警告。
- 安装包应包含应用图标、版本号、版权信息和卸载方式。

## 12. 验收标准

以下测试应在 Windows、macOS、Linux 至少各执行一次；测试服务器应提供可校验的固定测试文件。

| 编号 | 验收场景 | 通过条件 |
| --- | --- | --- |
| AC-01 | 输入一个普通 HTTPS 直链并开始下载 | 任务进入下载中，进度、速度、ETA 正常更新，完成后文件可打开 |
| AC-02 | 下载 500 MiB 测试文件，服务器支持 Range | 观察连接数从 4 逐步爬升；块级动态调度生效；最终 SHA-256 与源文件一致 |
| AC-03 | 2 GiB 文件使用 16 通道，在受控服务器连续测试 3 次 | 中位吞吐可重复达到单连接的 6 倍以上，并达到 aria2c 同级配置的 85% 以上 |
| AC-04 | 服务器忽略 Range | 自动降级为单连接，文件内容正确，任务详情显示能力受限 |
| AC-05 | 下载中暂停 3 秒后继续 | 只补齐未写字节，不重新下载已完成数据，最终文件正确 |
| AC-06 | 下载中途结束进程并重新启动 | 任务显示为已暂停；继续后最终文件正确 |
| AC-07 | 下载中主动断开网络后恢复 | 任务自动重试或提示失败；重试成功后文件正确，分块无重叠缺口 |
| AC-08 | 暂停后服务器文件大小或 ETag 改变 | 程序阻止不安全续传，提示用户重新下载 |
| AC-09 | 文件名包含中文、空格和括号，并存在同名文件 | 文件名正确清理，自动追加序号，文件路径没有越出保存目录 |
| AC-10 | 服务器返回 404、403、TLS 错误 | 显示明确 HTTP/TLS 错误，不无限重试，任务保留可查看 |
| AC-11 | 保存目录无写权限或可用空间不足 | 任务失败或暂停，不产生被误报完成的文件 |
| AC-12 | 默认配置下同时添加 3 个任务 | 只有 1 个活动任务使用全部连接预算，其余任务排队；当前任务结束后自动开始下一个 |
| AC-13 | 用户开启 2 个活动任务 | 每个任务按连接预算上限运行，界面提示带宽和连接会被分摊 |
| AC-14 | 下载 5 GiB 文件 | 大小和进度使用 64 位计算，最终大小和 SHA-256 正确，无溢出 |
| AC-15 | 服务器故意停止发送数据 10 秒 | 速度在数据耗尽后降为 0，进度停止；界面不得继续制造虚假推进 |
| AC-16 | 总大小未知的流式响应 | 显示不确定进度、已写字节和真实速度，不显示伪造百分比或 ETA |
| AC-17 | 连续滚动历史列表并开启默认动效 | 下载线程不被阻塞，主界面保持可操作，动画可自动降级 |
| AC-18 | 关闭应用时存在活动任务 | 任务暂停并保存，下一次启动能够恢复 |
| AC-19 | 输入 `file://`、空 URL 或非法协议 | 在开始前被拒绝，不产生网络任务 |
| AC-20 | 使用系统代理下载普通直链 | 默认遵循系统代理配置；代理不可用时能显示错误 |
| AC-21 | 完成、暂停、失败三种任务在列表中操作 | 按钮与状态匹配，删除本地文件必须二次确认 |
| AC-22 | 开启“性能优先”动效模式 | 粒子、模糊和连续动画关闭，核心信息仍完整，下载速度不受界面影响 |
| AC-23 | 三平台启动发布包 | 主窗口、选定 IP 主题或中性占位主题、设置、添加任务和打开目录功能可用 |
| AC-24 | 检查公开构建包内的主题资源 | 只包含已授权素材；主题清单、版权方和许可说明齐全；无本地私有 IP 主题被误打包 |

### 12.1 测试工具建议

- 本地 HTTP 测试服务器：提供支持 Range、忽略 Range、重定向、延迟响应、断连和可控 ETag 的测试端点。
- 文件校验：使用固定测试文件和 SHA-256 对照。
- 网络异常：通过本地代理、临时断网或服务器主动断开模拟。
- 磁盘异常：使用小容量虚拟磁盘或只读目录模拟空间不足和权限错误。
- 崩溃恢复：在分块写入过程中强制结束进程，再启动检查数据库与临时文件。
- 性能基准：使用固定测试文件、aria2c 对照组、冷缓存/热缓存标记和至少 3 次中位数统计。
- 进度真实性：通过服务器限速、暂停和中断模拟，记录 UI 速度/进度与磁盘实际写入字节的差异。
- 视觉验收：截取空状态、下载中、速度爬升、限速降级、完成和失败六种状态，确认进度与状态表达真实一致。

## 13. 实施里程碑

以下估算基于一名熟悉 Qt 的开发人员全职投入，不包含应用商店审核和签名证书申请时间。

| 阶段 | 工作内容 | 预计时间 |
| --- | --- | --- |
| M0 | 需求冻结、候选热门 IP 与授权状态确认、libcurl multi + Qt QML 技术验证、三平台构建环境 | 1～2 天 |
| M1 | CMake 工程、QML 主框架、任务模型、动画性能基线 | 2～3 天 |
| M2 | URL 探测、单连接下载、动态分块、工作窃取、连接爬升 | 5～7 天 |
| M3 | 暂停恢复、SQLite、重试、背压、校验和原子落盘 | 4～6 天 |
| M4 | 热门 IP 主题包接入、速度曲线、连接通道、队列历史和设置 | 4～6 天 |
| M5 | 性能基准、三平台打包、异常测试、签名检查和发布说明 | 4～6 天 |

目标：

- 3～4 周完成“可试用核心”：能单任务极速下载、暂停恢复、真实进度和可运行界面。
- 6～8 周完成具备发布质量的 MVP：包含已授权 IP 主题接入、性能基准、三平台打包和完整异常测试。
- 若只能利用业余时间，预计需要 8～12 周。
- IP 授权谈判、合同审批和官方素材交付通常不由开发团队控制，不包含在上述工程周期内。

## 14. 风险与应对

| 风险 | 影响 | 应对 |
| --- | --- | --- |
| 不同服务器对 Range、Content-Range 的实现不一致 | 可能拼接错误或降级失败 | 严格校验 206 响应；无法确认时降级单连接；建立多类型测试服务器 |
| 服务器按 IP 或账号限速 | 16～32 连接不一定明显加速 | 渐进爬升、吞吐停滞判断、429 自动降级；界面明确展示真实瓶颈 |
| 高并发触发服务器封禁 | 任务失败或 IP 临时不可用 | 默认 16、硬上限 32；禁止用户无上限配置；错误时自动退避 |
| 磁盘写入成为瓶颈 | 网络速度看似高但进度跟不上 | 预分配、随机写、有界缓冲和背压；调试面板展示磁盘吞吐 |
| libcurl 和 TLS 依赖的跨平台打包复杂 | 三平台行为或安装包不一致 | 固定版本、统一构建参数、尽早做三平台 CI 烟测 |
| Qt 动画与下载并发抢占资源 | 界面美化拖慢核心 | 独立线程、动画降级、性能优先模式、发布前做性能基准 |
| “工业级”目标过高导致延期 | 长期无法形成可用版本 | 把极速核心、恢复正确性和真实进度设为不可妥协项；管理类功能保持简单 |
| 二次元视觉被误做成装饰动画堆叠 | 好看但不实用或性能差 | 视觉必须服务速度、连接和状态表达；所有动效可关闭 |
| 热门动漫 IP 未获授权、授权费用过高或谈判周期过长 | 公开版本无法合法分发，视觉工作被迫重做 | 主题包与代码解耦；开发期使用中性占位；先确认 IP、发布范围和权利方，再采购或制作正式素材 |
| 官方素材规格不适合桌面 UI | 角色图裁切差、信息层级混乱 | 在授权允许范围内进行主视觉适配；提前确认是否允许裁切、重绘和动态化 |
| Qt LGPL 和商业发布方式冲突 | 影响闭源或商店发布 | MVP 采用动态链接并整理第三方许可证；商业场景单独评估授权 |
| macOS 公证、Windows 签名缺失 | 用户安装时被拦截 | 开发阶段使用本地构建；公开发布前准备开发者账号和签名流程 |
| 临时文件占用空间 | 大文件需要额外磁盘空间 | 预分配并优先定位写入；启动前检查空间；明确失败提示 |
| 关闭程序或崩溃丢失最后进度 | 少量数据需重下 | 每 1 秒/8 MiB 持久化；最终以写入字节数为准 |
| UI 功能膨胀导致延期 | MVP 无法按期交付 | 严格锁定 P0，P1 功能不进入首版 |

## 15. 待确认事项

以下事项不阻塞技术骨架开发，未确认前按括号中的默认值执行：

1. 产品正式名称与图标（默认暂用“QuickDL”）。
2. 要使用哪一个热门动漫 IP、希望出现哪些角色和主视觉。
3. 对应 IP 的权利方、授权代理或合作渠道是谁。
4. 发布范围是仅本机自用、免费公开还是商业发布。
5. 当前授权状态：已有书面许可、正在接触、尚未联系，暂时只做本地主题。
6. 项目是否开源（默认按可公开分发的 LGPL 合规方式设计）。
7. macOS Intel 是否纳入首个公开包（默认支持 Intel 与 Apple Silicon）。
8. Windows ARM64、Linux ARM64 是否进入首版（默认 P1）。
9. 是否需要浏览器扩展或剪贴板自动监听（默认不进入 MVP）。
10. 是否需要在 MVP 中加入全局限速、多链接批量下载（默认 P1）。

在未确定具体 IP 前，开发默认使用“IP Theme Slot”中性占位主题。它只负责验证布局、动效和性能，不包含任何未授权的动漫角色或 Logo。

## 16. 发布完成定义

满足以下条件后，MVP 才可以标记为可试用版本：

- 所有 P0 功能完成，并通过第 12 节验收用例。
- 至少完成一次“进程被强制终止后恢复”的整文件校验。
- 完成第 11.3 节的性能测试，并保留测试环境、连接数、中位数和 aria2c 对照结果。
- 默认二次元主题完成视觉验收，进度、速度、连接状态和角色动效均与真实数据一致。
- 如果公开发布热门 IP 主题，必须具备覆盖该发布渠道、地区、期限和使用方式的书面授权；否则公开包只能使用中性占位主题。
- “性能优先”动效模式可用，关闭装饰效果后核心功能和进度展示不缺失。
- Windows、macOS、Linux 均有可启动的发布包，且基础操作可用。
- Qt、libcurl、TLS 依赖和视觉资源的许可证、版本信息、图标及应用标识齐全。
- 日志位置、错误提示和设置持久化行为可被测试人员理解。
- 没有已确认的破坏性数据丢失问题、错误完成标记或不可恢复的启动崩溃。
- 发布说明中明确支持的协议、平台、已知限制、性能测试条件和“不保证所有服务器加速”的边界。
