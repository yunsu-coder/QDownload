## 2. 产品定义

### 2.1 一句话定位

**一个以单任务极速下载为核心的 Qt 原生桌面工具：操作简单、数据真实、视觉为帅气强大的佐助主题。**

### 2.2 本轮要验证的核心命题

- 单个大文件能否比浏览器或普通单连接下载更快。
- 暂停、继续和错误状态是否可信、可解释。
- 速度、进度、ETA 和连接通道是否来自真实传输数据。
- 原生 Qt 窗口是否符合二次元审美，而不是套壳网页后台。
- 用户是否愿意长期用它替代付费下载器处理大文件。

### 2.3 产品优先级

| 优先级 | 内容 | 说明 |
| --- | --- | --- |
| 1 | 单任务极速 | 默认把全部连接预算交给当前文件 |
| 2 | 数据真实 | 不允许虚假进度、虚假速度、虚假连接数 |
| 3 | 恢复可靠 | 暂停、继续、失败重试、重启恢复 |
| 4 | 视觉有辨识度 | 佐助主题、速度仪表、真实连接通道 |
| 5 | 操作简单 | 粘贴直链即可开始，队列不是主界面中心 |

## 3. 本轮原型范围

### 3.1 原型形态

本轮建议交付一个**可直接运行的原生 Qt 桌面原型**，而不是只有界面截图。

建议首个验证平台：

- macOS Apple Silicon，使用当前机器已有的 Qt 6.11.1。
- 代码结构保持 Windows / Linux 可移植。
- Windows、Linux 的实际构建与打包不作为本轮必交项，除非另行批准。

### 3.2 必做功能（P0）

| 编号 | 功能 | 验收口径 |
| --- | --- | --- |
| P0-01 | 粘贴 HTTP/HTTPS 直链 | 空地址、非法协议必须被拒绝 |
| P0-02 | 选择下载目录 | 默认系统下载目录，可改；本轮可简化 |
| P0-03 | 真实下载文件 | 必须写入真实文件，不使用模拟进度 |
| P0-04 | 单任务多连接下载 | 在服务器支持 Range 时至少 4 路并行；目标默认 16 路 |
| P0-05 | 真实进度与速度 | 进度只按已写入磁盘字节计算；速度为真实采样 |
| P0-06 | 真实 ETA | 样本不足时显示“计算中”，不伪造精确秒数 |
| P0-07 | 暂停/继续 | 继续时不得重新下载全部已完成数据 |
| P0-08 | 错误反馈 | 网络失败、HTTP 错误、磁盘错误有明确说明 |
| P0-09 | 打开下载目录 | 完成后能直接定位文件 |
| P0-10 | 佐助主题主界面 | 本地非商业素材；速度、进度、连接通道是真实状态映射 |
| P0-11 | 单任务优先 | 默认只运行一个任务，其他任务不进入本轮原型 |
| P0-12 | 原生桌面窗口 | 使用系统窗口边框和 Qt 原生应用行为，不做网页式全屏页面 |

### 3.3 原型可简化项

- 只保留一个当前任务，不做完整任务队列。
- 不实现下载历史。
- 不实现多任务并发。
- 不实现设置页，只保留目录选择。
- 不实现自动更新、托盘、系统通知。
- 不实现浏览器扩展、剪贴板监听。
- 不实现视频网站解析、登录态、BT、磁力链接。

### 3.4 明确不做（本轮）

- 网页前端、Electron、Tauri、任何 WebView。
- Figma 画板或 Figma 插件。
- 视频站点解析、Cookie、会员账号模拟。
- 任务队列管理后台。
- 云同步、账号系统。
- 公开分发佐助官方图或未授权同人素材。

## 4. 核心交互流程

### 4.1 主流程

1. 打开 QuickDL 原生窗口。
2. 粘贴 HTTP/HTTPS 直链。
3. 显示目标文件名和保存目录。
4. 点击“极速下载”。
5. 程序探测文件大小与 Range 支持。
6. 在支持 Range 时启动多个连接；不支持则降级单连接。
7. 主舞台显示真实速度、真实写盘进度、ETA、实际活跃通道数和速度曲线。
8. 用户可以暂停、继续、失败重试、打开目录。

### 4.2 状态

`Idle → Probing → Downloading ⇄ Paused → Completing → Completed`

异常路径：

`Downloading → Failed → Retrying → Downloading`

### 4.3 界面结构

```text
原生窗口
├── 系统标题栏
├── 顶栏：QUICKDL 标识、当前状态、佐助主题标识
├── 下载输入栏：URL、保存目录、极速下载
├── 当前任务主舞台
│   ├── 文件名与状态
│   ├── 大号真实速度
│   ├── 真实写盘进度环
│   ├── 进度条、已下载/总大小、ETA
│   ├── 60 秒真实速度曲线
│   ├── 实际连接通道
│   └── 暂停/继续、重试、打开目录
├── 引擎信息侧栏：连接数、状态、错误
└── 本地非商业原型说明
```

## 5. 视觉与素材审计

### 5.1 视觉方向

- 深黑、暗紫、写轮眼红、雷遁蓝。
- 大号速度数字、径向真实进度环、真实速度曲线。
- 佐助角色作为主视觉，但不遮挡操作和错误提示。
- 保持“帅气、强大、克制”，避免普通后台仪表盘感。
- 默认客户端为原生桌面窗口，保留系统标题栏。

### 5.2 佐助素材边界

- 当前仅用于用户本机非商业原型。
- 图片放在本地资源目录，不用于公开安装包。
- 如果未来公开分发或商业化，必须替换为已授权素材或取得正式许可。
- 本审计稿不将“非商业”视为法律结论，只定义当前使用边界。

## 6. 技术方案审计

### 6.1 推荐方案

| 层 | 建议 |
| --- | --- |
| 应用框架 | Qt 6 + CMake |
| UI | Qt Quick / QML |
| 业务层 | C++20 |
| 传输核心 | libcurl multi |
| 持久化 | 本轮可不接 SQLite；先验证单任务传输 |
| 平台 | macOS 先跑通，结构保持 Windows/Linux 可移植 |

### 6.2 为什么本轮不建议只用 Qt Network

Qt Network 足以完成单连接下载，但用户的核心诉求是单任务极速。若原型只验证单连接：

- 无法验证多连接调度、Tail 问题、并发降级。
- 无法展示“实际活跃通道”与真实吞吐。
- 后续换 libcurl 时，传输层需要重写，原型价值降低。

因此建议从本轮开始使用 **libcurl multi**，即使最初只开 4～8 路。

### 6.3 本轮连接策略

- 服务器支持 Range 时：先 4 路验证，目标 16 路。
- 不支持 Range：诚实降级为单连接，并标记能力限制。
- 用户可设置连接数，但本轮 UI 可先固定在 16 上限。
- 实际活跃通道数必须来自正在运行的传输请求，不用装饰动画冒充。

### 6.4 数据真实性约束

- 进度：只统计已确认写入磁盘的字节。
- 速度：按真实完成字节和时间窗计算。
- ETA：至少 2 秒有效样本后才显示。
- 连接通道：每个亮起的通道都必须对应真实请求。
- 失败或暂停：速度归零，进度冻结，不继续向前动画。

## 7. 验收标准

只有满足以下条件，原型才算可提交：

- 能下载一个真实 HTTP/HTTPS 文件，最终文件大小正确。
- 服务器支持 Range 时，至少验证 4 路并行请求；最终目标 16 路。
- 暂停后继续，已下载部分不全部重来。
- 界面进度与磁盘实际写入一致。
- 速度、ETA、活跃通道数来自真实状态。
- 错误场景有明确提示，不假报完成。
- 原生窗口可启动，不依赖浏览器或 WebView。
- 佐助素材仅存在本地资源目录。
- 提供一张运行截图或录屏作为交付证据。
